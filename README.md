## 主张

企业不写作文，只喂素材、挂证据；审核员不通读全文，只验结论。
约 60% 的审核成本前移到提交端由 AI 承担，其余的用风险分级压成审核员必须亲自判断的 5 个问题。

## 原型怎么点（30 秒演示）

1. **挂证据**：点任意证据胶囊（例如「客户授权」）→ 右侧可信度分、三条指标、模块状态点、问题清单同时变化。
2. **改写表述**：问题行右侧的「改写表述」把「行业领先 / 一站式 / 头部」换成可核验的事实句，并标为「AI 改写 · 待人确认」。
3. **分流结果**：初始 69 分落在「快审 · 5 分钟」；点「补齐演示」并清掉剩余问题后到 99 分，分流变成「自动通过 · 抽检 10%」，弧环变绿。
4. 右上角 **中文 / EN** 全量切换；系统深色模式自动跟随。

分数由前端规则实时计算（不是真模型）——先验证「挂证据 → 预审 → 分流」这条链路是否成立，再决定要不要接模型。

## 用到的工具

- **Cursor、pi agent**（日常主力开发工具）：把六模块落成字段结构、把「什么算通过」写成可执行规则清单，再反过来扮演审核员挑这套方案的漏洞。
- **Qoder**：提纲整理、证据类型归并、多版本对比。
- **DeepSeek（API 接入）**：做「宣称与证据对齐」的提示词对照试验（同批样例跑多组提示词、比较误判方向），据此划定必须留给人判的边界。

## 说明

- 原型内所有企业、案例、客户与数据均为**虚构示例**（星野数字营销），不含任何真实客户机密资料。
- 诚实边界：S0/S5 与 B 方案的 OCR 链路为设计推演，未接真实数据；A 的规则清单与 C 的风险打分已用样例跑通。
- 页面无外部依赖、无第三方请求、无埋点；字体走系统栈（SF / 苹方 / Inter 回退）。
- 可访问性：`prefers-reduced-transparency` 退化为不透明、`prefers-reduced-motion` 关闭动效、全控件可见焦点环。
